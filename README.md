# robot_vision

이족보행 로봇의 비전 패키지. Insta360 카메라 보정 실행 도구와 C++로 작성한 빨강·파랑 40cm 정사각형 면의 거리 추정 노드를 제공합니다.
직선 검출과 로봇/바닥 좌표 변환은 이후 단계입니다.

## 1. 준비

```bash
cd ~/colcon_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select robot_vision
source install/setup.bash
```

기존 insta360_usb_cam 패키지도 빌드되어 있어야 합니다.
처음 빌드한다면 `colcon build --packages-up-to robot_vision`을 사용합니다.
체커보드 보정을 실행할 때만 `sudo apt install ros-jazzy-camera-calibration`이 필요합니다.

체커보드를 평평하고 단단한 판에 붙입니다. 가로/세로 **내부 교차점**을 세고,
한 칸의 실제 변 길이를 자로 측정합니다. 9×7칸은 내부 교차점 8×6개입니다.
인쇄 크기를 임의로 가정하지 마세요. 초점과 줌은 실제 사용할 설정으로 고정하고,
보정 이후 해상도/크롭/줌/초점을 바꾸면 보정의 유효성을 다시 확인합니다.

## 2. 실행

아래는 **내부 교차점 8×6, 실제 한 칸 25 mm인 경우의 예시**입니다.
반드시 자신의 측정값으로 바꿉니다. 두 값은 기본값 없이 필수 입력입니다.

```bash
ros2 launch robot_vision calibrate.launch.py board_size:=8x6 square_size:=0.025
```

카메라가 이미 실행 중이면 `start_camera:=false`를 추가합니다.
카메라 실행 파일이 Insta360 Link의 캡처 장치를 자동으로 찾습니다.
화면이 표시되는 로컬 데스크톱 터미널에서 실행합니다.

## 3. 촬영 및 저장

체커보드 전체가 보이게 하면서 화면 중앙과 네 모서리로 이동하고,
가까이/멀리, 좌우/위아래로 기울인 모습을 모읍니다. 흐린 영상은 피하고 잠깐씩 멈춥니다.
도구의 X, Y, Size, Skew 수집 상태를 확인한 뒤 CALIBRATE를 누릅니다.
보정 결과와 보정된 영상의 직선 상태를 확인하고 SAVE로 결과를 저장합니다.
저장 경로는 도구의 터미널 출력에서 확인하고 결과 파일을 영구 보관합니다.

현재 드라이버는 `set_camera_info` 서비스를 제공하지 않습니다.
따라서 `--no-service-check`로 시작하며 COMMIT을 통한 자동 적용은 지원하지 않습니다.
SAVE 결과는 새 보정값을 확인하고 적용하는 다음 단계의 입력입니다.

## 현재 드라이버에서 확인한 사항

- 실제 출력은 `sensor_msgs/Image`, BGR8, 640×480입니다. 토픽 이름은 `/camera1/camera/compressed_image`입니다.
- 출력은 usb_camera.cpp에서 640×480으로 고정 리사이즈됩니다.
- 기존 CameraInfo의 해상도와 행렬이 실제 출력에 맞는지 별도 검증이 필요합니다.
  이번 보정은 이미지에서 새 값을 구하며 기존 CameraInfo를 사용하지 않습니다.
- 기존 보정 파일에 새 값을 단순 복사하는 것만으로 적용 완료라고 판단하면 안 됩니다.
  실제 발행 영상 크기와 CameraInfo가 일치하는지 확인해야 합니다.
- 내부 보정은 렌즈 왜곡과 카메라 내부 행렬을 구합니다. 장애물의 미터 단위 위치는
  이후 카메라 장착 자세와 바닥 기준점으로 별도 보정합니다.

공식 도구: https://index.ros.org/p/camera_calibration/


## 빨강·파랑 장애물 거리 추정

대상은 **보이는 단색 정사각형 면의 가로·세로가 각각 40cm**인 장애물입니다.
HSV로 빨강/파랑 영역을 분리하고, 네 모서리와 실제 크기를 OpenCV PnP에 입력합니다.
빨강은 HSV 색상각의 양 끝 범위를 함께 처리합니다. 여러 장애물을 동시에 출력합니다.

### 실행

아래 명령 하나로 카메라와 거리 측정 노드를 함께 실행합니다.

```bash
cd ~/colcon_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select robot_vision
source install/setup.bash
ros2 launch robot_vision obstacle_distance.launch.py
```

`Obstacle distance - RED / BLUE - 40cm` 창에 결과를 표시합니다.
카메라가 이미 실행 중이면 `start_camera:=false`를 추가해 중복 실행을 피합니다.
GUI 없는 환경은 `viewer:=false`를 추가하고 `/vision/obstacle_debug`를 뷰어로 봅니다.
파라미터를 변경할 때는 설정 파일을 편집한 뒤 노드를 재시작합니다.
소스 설정을 직접 사용할 경우:

```bash
ros2 launch robot_vision obstacle_distance.launch.py config_file:=$HOME/colcon_ws/src/robot_vision/config/obstacle_distance.yaml
```

### 화면과 출력

- `RANGE`: 카메라 광학 중심에서 **보이는 정사각형 면의 중심**까지 직선거리(m).
- `Z`: 카메라가 바라보는 방향으로의 깊이(m).
- `X`: 카메라 기준 좌우 위치(m), 오른쪽이 양수. Y는 아래쪽이 양수입니다.
- `/vision/obstacles`: `robot_vision/msg/ObstacleArray`. 영상 촬영 시각, 색상, XYZ, 거리, 네 모서리와 재투영 오차를 발행합니다.
- `/vision/obstacle_debug`: 거리와 테두리를 그린 BGR 영상.
- `/vision/obstacle_mask`: 빨강/파랑으로 분리된 영역. 검출이 안 되면 이 영상을 보고 HSV 범위를 조절합니다.
- 감지되지 않는 프레임에는 빈 목록을 발행합니다. 영상이 1초 이상 끊기면 `image_timeout`과 빈 목록을 발행하고 화면을 지웁니다.
- 위치 좌표계 이름은 `camera1_optical_frame`입니다. 현재 TF는 제공하지 않으며 로봇 몸체 기준 위치나 바닥상의 수평거리가 아닙니다.

### 정확도와 사용 조건

현재 K/D는 insta360_usb_cam의 기존 값이며, **640×480 영상용이라는 가정은 아직 검증되지 않았습니다.**
따라서 `calibration_verified: false`가 기본값이고 화면과 메시지 모두 미확인 상태를 표시합니다.
기존 카메라의 CameraInfo 해상도 불일치 가능성 때문에 거리 노드는 그 토픽 대신 명시적인 K/D를 읽습니다.
실제 영상 크기가 설정과 다르면 수치 출력을 중단합니다. 단순 자동 스케일링은 하지 않습니다.

먼저 장애물 면을 정면으로 놓고 카메라 렌즈 부근부터 면 중심까지 실제 1m, 1.5m, 2m에서 비교하세요.
그다음 화면 좌우와 비스듬한 자세에서도 확인하세요. 화면의 추정 거리와 실측 거리 차이를 기록하고,
필요하면 새 체커보드 보정으로 K/D를 교체합니다. 임의 거리 보정 계수는 적용하지 않습니다.

색상만으로 물체의 종류나 실제 크기를 증명할 수 없습니다. 같은 색 사각형 배경도 후보가 될 수 있습니다.
네 모서리와 면 전체가 보일 때 사용하며 화면 가장자리에서 잘린 대상, 작은 영역, 원/삼각형,
직사각형 모델과 맞지 않는 후보는 제외합니다. 가림이나 같은 색 물체끼리 붙은 경우 검출에 실패하거나 오검출할 수 있습니다.
재투영 오차가 작아도 잘못된 K/D나 실제 크기 오류는 검출하지 못하므로 실측 검증이 필요합니다.

알고리즘 검증: `colcon test --packages-select robot_vision` 다음 `colcon test-result --verbose`
C++ 검사에서 알려진 거리, 두 색 동시 검출, 겹친 파란 면, 화면 경계와 해상도 불일치를 확인합니다.
이 검사는 실제 카메라의 거리 정확도 검증을 대신하지 않습니다.

PnP 및 좌표계 공식 문서: https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html

### 진한 파란색 설정

파란색 HSV 범위를 `H=105~125, S=170~255, V=45~255`로 좁혔습니다.
이전에 촬영된 파란 장애물 화면의 내부 픽셀 중 약 99%가 이 범위에 들어옵니다.
잔디의 녹색/청록색 오검출을 줄이는 목적입니다. 실외 조명에서 놓치는 경우
`/vision/obstacle_mask`를 보고 `config/obstacle_distance.yaml`의 blue 범위를 조정하세요.
수정 후 재빌드하고 노드를 다시 실행해야 적용됩니다.

### 조금 불규칙한 사각형

검출된 색 영역의 외곽이 약간 울퉁불퉁하거나 한쪽 변에 작은 빈 부분이 생겨도
그 외곽을 감싸는 네 모서리를 추정합니다. 추정 사각형과 실제 색 영역의
겹침률(IoU)이 `min_fill_ratio`보다 낮으면 거리값을 내보내지 않습니다.
기본값은 0.80입니다. 원과 삼각형 또는 화면 밖으로 잘린 물체는 계속 제외합니다.

거리 계산에는 **물체의 실제 보이는 면이 40×40cm**라는 가정이 들어갑니다.
색상 마스크의 울퉁불퉁함은 허용할 수 있지만, 실제 면 크기가 다르거나
네 모서리 중 하나가 가려지면 거리에 체계적인 오차가 생길 수 있습니다.

### 서로 붙어 보이는 파란 장애물

앞뒤 파란 면이 영상에서 하나의 색 영역으로 이어지면 일반적인 사각형 검출이 실패할 수 있습니다.
먼저 채도 차이로 앞면을 분리하고, 실패하면 영상에서 보이는 네 변으로 정면에 가까운
파란 면을 추정합니다. 분리된 거리는 화면에 `~`를 붙여 표시하며 `/vision/obstacles`의
`color_split_estimate`도 `true`로 발행합니다. 네 변이 충분히 보이지 않으면
거리값을 내지 않습니다. 분리한 테두리는 근사값이므로 실제 거리와 비교해 사용하세요.
가까운 빨간 면을 놓치던 재투영 오차 허용값은 3.5픽셀로 조정했습니다.
